# 04 — API Design

## Conventions

- Base path: `/api/v1` — versioned from day one.
- JSON only; timestamps ISO-8601 UTC; dates ISO `YYYY-MM-DD`; money in rupees
  (decimal numbers, never strings).
- Auth: `Authorization: Bearer <access-token>` (JWT, 30 min). Refresh tokens
  (14 days) are redeemed at `POST /auth/refresh`.
- Errors use RFC-7807-style detail via FastAPI's `{"detail": ...}` plus a
  machine-readable `code` field for known business errors.

| Code | HTTP | Meaning |
|---|---|---|
| `DISCLAIMER_REQUIRED` | 403 | current disclaimer version not accepted |
| `INVALID_CREDENTIALS` | 401 | bad login |
| `ACCOUNT_LOCKED` | 423 | too many failed attempts (temporary) |
| `TOKEN_EXPIRED` | 401 | refresh/access expiry |
| `VALIDATION_ERROR` | 422 | request body failed schema validation |
| `RATE_LIMITED` | 429 | too many requests |

- Interactive docs: `/docs` (OpenAPI 3.1 generated by FastAPI).

## Rate limiting (Phase 1: in-process sliding window)

| Endpoint group | Limit |
|---|---|
| `POST /auth/login`, `/auth/register`, `/auth/password/*` | 10 / 5 min per IP |
| authenticated mutations | 120 / min per user |
| reads | 300 / min per user |

## Endpoint catalogue — Phase 1

### Auth & profile
```
POST   /auth/register              create account (email or mobile) + disclaimer acceptance
POST   /auth/login                authenticate (accepts accepted disclaimer version)
POST   /auth/refresh              rotate access token
POST   /auth/logout               revoke refresh session
GET    /auth/me                   current user profile
PATCH  /auth/me                   update profile
POST   /auth/change-password
GET    /auth/sessions             active sessions (device, last used)
DELETE /auth/sessions/{id}        revoke one session
POST   /auth/password/forgot      request reset (returns token only in DEV)
POST   /auth/password/reset       complete reset with token
```

### Expenses & income
```
GET    /expenses                  list (filters: date range, category, q, page/page_size)
POST   /expenses
GET    /expenses/{id}             PATCH /expenses/{id}   DELETE (soft) /expenses/{id}
GET    /expenses/categories       system + custom categories
POST   /expenses/categories       custom category
DELETE /expenses/categories/{id}  custom category (if unused)
GET    /incomes                   POST /incomes
PATCH  /incomes/{id}              DELETE /incomes/{id}
```

### Budgets
```
GET    /budgets                   list with live status (actual, remaining, utilization, alerts)
POST   /budgets
PATCH  /budgets/{id}              DELETE /budgets/{id}
```

### Analytics & AI (Phase 1 scope)
```
GET    /analytics/dashboard       one-shot dashboard payload (snapshots + series + insights)
GET    /analytics/summary         totals & rates for a period
GET    /analytics/trends          daily/monthly series, MoM/YoY deltas
GET    /analytics/categories      distribution + top merchants
GET    /analytics/anomalies       z-score flagged transactions (explained)
GET    /analytics/insights        generated insights, each citing its data
GET    /analytics/health-score    transparent weighted score + factor breakdown
```

### Market analysis (Phase 2 — increment 1; recorded-sample provider)
```
GET    /market/symbols              symbols the provider can serve (+coverage window)
GET    /market/{symbol}/analysis    indicators + valuation + scenarios + score, one payload
POST   /market/{symbol}/valuation   re-value under user-editable assumptions (422 on infeasible ones)
```
Assumptions accepted by `POST /market/{symbol}/valuation`
(defaults shown): `projection_years=5`, `stage1_growth_pct=14`,
`terminal_growth_pct=4.5`, `wacc_pct=10.5`, `pe_target=22`,
`ev_ebitda_target=14`, `ddm_growth_pct=4.5`, `required_return_pct=10.5`.
Unknown symbols → 404; terminal growth ≥ WACC → 422. Every response is
labelled with its `source` (currently `recorded-sample`) and carries the
not-investment-advice disclaimer.

### Financial calculators (Phase 3 items pulled forward; deterministic engines)
```
POST   /calculators/fd             fixed-deposit maturity
POST   /calculators/mutual-fund    SIP + lumpsum projection
```
`fd`: principal, rate, tenure (years + months), compounding frequency
(yearly/half_yearly/quarterly/monthly), optional senior-citizen bonus,
income-tax slab (post-tax view) and inflation (real-value view); returns
maturity, interest, effective annual yield and a year-by-year schedule.

`mutual-fund`: monthly SIP and/or lumpsum, expected return, annual step-up,
expense ratio (charged off the return), inflation view and an optional goal
target (goal-seek inverts the projection exactly). Returns invested, final
value, gain, money-weighted annualised return (XIRR via bisection), the TER
cost in rupees and a yearly schedule. Infeasible inputs → 422.

### Admin (role: admin; least privilege — no access to user financial data)
```
GET    /admin/overview            users, activity, feature usage counters, system health
GET    /admin/users               search & list accounts
PATCH  /admin/users/{id}          activate/deactivate, change role
GET    /admin/audit-logs          filterable audit trail
GET    /admin/login-activity      successes/failures timeline
```

### Meta
```
GET    /healthz                   liveness (public)
GET    /config/disclaimer         current disclaimer text + version (public)
```

## Response shape example — `GET /analytics/health-score`

```json
{
  "score": 72,
  "grade": "Good",
  "factors": [
    {
      "key": "savings_rate",
      "label": "Savings rate",
      "weight": 0.25,
      "effective_weight": 0.45,
      "factor_score": 78,
      "contribution": 35.1,
      "status": "evaluated",
      "explanation": "You saved 15.6% of income over the last 3 months.",
      "suggestions": ["Raise savings above 20% to max this factor."]
    },
    {
      "key": "diversification",
      "status": "not_evaluated",
      "reason": "Requires portfolio holdings (Phase 3 module)."
    }
  ]
}
```
Weights of not-evaluated factors are redistributed — the model never invents
data (see `05-ai-ml-architecture.md`).
