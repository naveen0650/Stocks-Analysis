# 05 — AI / ML Architecture

## Principles

1. **No hallucinated finance.** Every generated insight cites the aggregated
   numbers it was computed from. If data is insufficient, the system stays
   silent — it never fabricates.
2. **Statistical first, learned later.** Phase 1 uses transparent statistics;
   Phase 2–3 swap in learned models *behind the same function signatures* so
   the API surface never changes.
3. **Explainability is a feature.** Scores decompose into weighted factors;
   anomaly flags carry their z-scores and the reference distribution.

## Phase 1 (implemented)

### Anomaly detection — z-score
For each transaction in the evaluation window, within its category:

```
z = (amount − μ_category) / σ_category     (requires n ≥ 8 history samples)
```
Flagged when `|z| > 2.5`. A second pass scores **daily totals** against the
user's last 90 days of daily spending. Every flag returns: amount, μ, σ, z,
the reference window, and a plain-language explanation.

### Insight generation — guarded rule engine
Deterministic rules, each with a data-sufficiency guard:

| Rule | Fires when |
|---|---|
| Category spike | category spend > 1.2 × its 3-month average AND Δ ≥ ₹500 |
| Concentration | one category > 35% of monthly spend |
| Recurring load | ≥ 3 recurring merchants identified (same merchant+amount across ≥ 3 months) |
| Weekend pattern | weekend daily average > 1.3 × weekday average |
| Savings trend | month-over-month savings rate change > ±5 pp |
| Budget pressure | any budget ≥ its configured alert threshold |

Output: `{type, severity, title, message, evidence}` — `evidence` carries the
actual figures, which is also what the UI renders.

### Financial health score — transparent weighted model
| Factor | Weight | Mapping |
|---|---|---|
| Savings rate | 0.25 | 0–100 linear, capped at 20% savings |
| Expense-to-income | 0.20 | ≤0.5 → 100, ≥1.0 → 0 |
| Budget adherence | 0.15 | utilization ≤85% → 100, ≥120% → 0 |
| Recurring ratio | 0.10 | ≤30% → 100, ≥60% → 0 |
| Emergency fund | 0.15 | months of expenses covered (6+ → 100) |
| Diversification | 0.15 | portfolio-based (Phase 3) |

Factors lacking data are marked `not_evaluated` and their weight is
redistributed proportionally. The response includes every factor's
contribution — this is the dissertation's "explainable scoring" baseline.

## Phase 2 — increment 1 (implemented): market analysis engines

### Provider abstraction — no fabricated data
`app/market/providers/` defines `FinancialDataProvider` (daily OHLCV bars,
quote, fundamentals). The first implementation is **recorded-sample**:
deterministic JSON fixtures (`app/market/fixtures/`, regenerated by
`scripts/generate_market_fixtures.py`) labelled `recorded-sample` in every
response. Vendor providers (Alpha Vantage / Twelve Data / FMP) implement the
same interface once an API key is configured; missing data surfaces as 404 /
`None` fields, never as invented numbers.

### Technical indicators — pure functions (`app/market/indicators.py`)
| Indicator | Definition |
|---|---|
| SMA(n) | rolling arithmetic mean |
| EMA(n) | seeded with SMA of first n values, then `k = 2/(n+1)` recursive |
| RSI(14) | Wilder smoothing; loss-free window pins to 100, motionless window is neutral 50 |
| MACD(12,26,9) | EMA12 − EMA26; signal = EMA9 of the line; histogram = line − signal |
| Bollinger(20, 2σ) | SMA ± 2 × population standard deviation |
| Max drawdown | deepest peak-to-trough decline over the window |
| Annualised volatility | sample sd of daily log returns × √252 |

Outputs are lists aligned with the input; warm-up positions carry `null`.

### Valuation engine — transparent finance (`app/market/valuation.py`)
All methods are pure functions returning their full working:
- **DCF**: two-stage — `g₁` for years 1..N, Gordon terminal value off the
  final FCF, end-of-year discounting at WACC; bridge `net_debt` from
  enterprise to equity value; reports terminal-value share of EV.
- **DDM**: Gordon growth; returns *no value* when r ≤ g or no dividend.
- **P/E**, **EV/EBITDA**: target-multiple methods net of debt.
- **PEG**: `PE / EPS-growth`; ±15% around a benchmark PEG of 1.0 → verdict.
- **Sensitivity**: WACC × terminal-growth grid (infeasible cells `null`).
- **Scenarios**: bear/base/bull presets flex growth, WACC and multiples
  together; every scenario reports per-method upside vs the live price.

### Stock score — explainable weighted model
Same contract as the health score (weights, `not_evaluated` redistribution,
per-factor contribution):
| Factor | Weight | Mapping |
|---|---|---|
| Valuation upside (blended) | 0.30 | +30% → 100, −30% → 0 |
| PEG | 0.15 | ≤1.0 → 100, ≥3.0 → 0 |
| ROE | 0.20 | ≥18% → 100, ≤6% → 0 |
| 6-month return | 0.15 | +15% → 100, −15% → 0 |
| Max drawdown (6m) | 0.10 | 0% → 100, −40% → 0 |
| Annualised volatility | 0.10 | ≤15% → 100, ≥45% → 0 |

Grades: ≥70 Attractive, ≥55 Fairly Valued, ≥40 Expensive, else Avoid.
Every response carries the not-investment-advice disclaimer.

## Phase 2 (remaining) — NLP & research outputs
- Sentiment: rule-based (VADER-style finance lexicon) vs TF-IDF + linear SVM
  vs distilled transformer (e.g., `distilbert-base-uncased-finetuned-sst-2`
  or FinBERT) — Experiment 2 compares all three on a labelled sample with
  accuracy/precision/recall/F1.
- Topic extraction: keyword + TF-IDF n-gram ranking per stock.
- PDF research reports; price/fundamentals cache in PostgreSQL once a live
  provider is configured (Alembic migrations begin with that schema).

## Phase 3 (planned) — forecasting & portfolio intelligence
- Expense forecasting: moving average vs Holt linear vs ARIMA vs gradient
  boosting regression, evaluated by MAE/RMSE/MAPE with walk-forward splits.
- Portfolio risk: volatility, max drawdown, concentration (HHI), beta vs
  NIFTY 50 where price history is available.

## Phase 4 (planned) — RAG research assistant
```
query → intent detection → retrieval (news, filings, user portfolio)
      → analysis engine → LLM with grounded context → cited response
```
Answers must quote retrieved chunks; unanswerable queries return
"insufficient data", never speculation.

## Explainability roadmap
Phase 1 weighted factors (implemented) → Phase 2 per-rule evidence +
sentiment confidence → Phase 3 feature importance / SHAP for forecasting
models → Phase 4 citation-grounded LLM responses.

## Evaluation discipline
No accuracy claim without a measurable evaluation: every experiment documents
dataset, preprocessing, split strategy, metrics and limitations
(see `10-dissertation-mapping.md`).
